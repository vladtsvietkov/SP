# Звіт ЛР1 DewWindow
## Мета
Підготувати відтворюваний STM32 HAL проєкт для оцінки ризику конденсації,
перевірити його запуск у Wokwi та сформулювати вимірювані вимоги до сенсорної
підсистеми. Перша лабораторна перевіряє середовище, ініціалізацію, UART і LED;
читання сенсорів та продуктові епізоди належать наступним роботам.

## Продукт і вимоги
DewWindow порівнює температуру холодної поверхні з точкою роси повітря.
DHT22 дає температуру та відносну вологість, NTC — температуру поверхні,
BMP180 — атмосферний тиск для обчислення вологовмісту. Це непряма оцінка ризику:
поява води не вимірюється. У симуляторі ці входи задаються незалежно.

PRD містить FR01–10 з критеріями приймання, альтернативами та межами формул.
Magnus над водою застосовується лише при T=0…50 °C та RH=1…100 %.
Вологовміст має одиниці г/кг сухого повітря, тиск використовується в паскалях.
Невалідний або застарілий канал дає DEGRADED, а не висновок DRY.

| Властивість | Контракт продукту |
|---|---|
| Опитування | NTC 250 мс, BMP180 1000 мс, DHT22 2500 мс; допуск release +50 мс у номіналі. |
| Валідність | Максимальний вік NTC 1000 мс, BMP 3000 мс, DHT 6000 мс; checksum, ID і діапазони. |
| Ризик | Margin≤0 °C; повернення після margin≥1 °C протягом 5 с. APPROACH≤2 °C, DRY≥3 °C. |
| Команди | status, limits, episodes, export; перший байт відповіді≤250 мс; export≤2 с. Реалізація — ЛР3. |
| Журнал | 32 епізоди на SPI microSD, CRC32, два слоти/запис і read-back; реалізація — ЛР3. |
| Ресурси | C031C6: 32 КіБ flash, 12 КіБ RAM; фактичні стек/heap вимірюватимуться у ЛР3. |

Період DHT має запас до мінімальних 2 с із datasheet; NTC 4 Гц достатньо для
повільного теплового процесу. Запас 2/3 °C і гістерезис 1 °C є проєктними порогами,
а не сертифікованою похибкою. Ці вимоги ще не є результатом приймання повного продукту.

## Середовище й відтворюваність
Середовище: Ubuntu 24.04, Docker, STM32 HAL, Wokwi. Форма B, плата Nucleo-C031C6.
Контейнер запускався на Mac; фізична плата не використовувалася.
Компілятор ARM GCC 13.2.1, target Cortex-M0+ без апаратного FPU.
Збережено походження дозволеного SP-Boilerplate, ліцензії ST/CMSIS та прикладу Wokwi.
Додаткові модулі ADC/SPI взято зі ST HAL v1.0.1.

make build створює ELF/HEX/BIN у firmware/build через Docker, make clean видаляє
лише результати збірки. Параметр DOCKER дозволяє вказати фактичний шлях executable.
Форма B запускається командою Wokwi: Start Simulator; звичайний wokwi.toml
посилається на HEX/ELF цього проєкту. Монітор — UART Wokwi та RFC2217, порт4417.
Ліцензію Community збережено без активації trial.

Дві чисті збірки фінальної конфігурації завершилися без помилок і дали однакові
SHA-256 для всіх трьох форматів. Логи clean-final-1.log і clean-final-2.log та
hashes-final-1/2.txt збережені в docs/metrics/lab1. Перевірки виконані 06.11.2026.

| Артефакт | SHA-256 |
|---|---|
| ELF | bf8c7f182fc8a66f1e4a64c00fd9cf8257751c31e62e2cc8b1b0da38c8fefc8c |

| BIN | 76fd0551f6c6057ab9721dab34ecfe6afeb60cfccd03c1f9a7a6a0e065f8fa48 |

arm-none-eabi-size: text=15932, data=112, bss=2320 байт. Flash text+data=16044 байт;
data+bss=2432 байт включає секції резервування лінкера. Це не вимір фактичної
глибини стека і не доказ відсутності переповнення.

## Піни та ініціалізація
HSI/SYSCLK/AHB/APB=48 МГц. USART2 PA2/PA3 AF1 — 115200 8N1.
I²C1 PB8/PB9 AF6 — близько100 кГц. ADC1 PA0 — 12bit, clock12 МГц.
DHT DATA PA6 — GPIO. SPI1 PB3/PB4/PB5 AF0 і CS PB0 зарезервовано для носія;
375 кГц, mode0. LED PA5 збережено. Вимірювальні виходи PA1/PA4.
.ioc і Platform/board.c містять актуальну конфігурацію; додаткові init внесені вручну,
без заяви про повторну генерацію всього проєкту CubeMX.
SWD, VCP, LED і кварцові лінії не використовуються як чужі сигнали.

## Дослідження компонентів
| Компонент | Вибір і документ |
|---|---|
| AM2302/DHT22, GPIO | T/RH з checksum; 3.3…5.5 В, типовий measuring 1.2 мА, sampling≥2 с. Aosong Technical Manual V1.0 с.2,5–7. DHT11 відхилено через грубішу дискретність. |
| NTC10к, B3950, ADC | Контактний канал поверхні; дільник10к/10к, 0…3.3 В. Параметричний Wokwi аналог TDK B57891M0103J000; datasheet, електрична таблиця/характеристика4901. DS18B20 не дає ADC-каналу. |
| BMP180, I²C | Тиск у Па; 0x77, ID D0=0x55, AA…BF калібрування, F4 керування, F6…F8 результат. Bosch BST-BMP180-DS000-09 с.6,11–15,18–23. Константа тиску відхилена як невиміряна. |
| microSD, SPI | Вибраний носій для подальшого журналу; raw-сектори і статичний буфер512 байт. У ЛР1 лише ініціалізація SPI, збереження даних не заявляється. |

Сенсорний бюджет 3V3 оцінено приблизно4.1 мА із підтягуваннями, резерв10 мА.
Для фізичної microSD потрібен окремий стабілізатор3.3 В із запасом≥250 мА;
точний peak конкретної карти треба перевірити після вибору носія.
Струм, rise time, контакт NTC зі склом і теплове самонагрівання симулятором не вимірюються.
Офіційні datasheet і сторінки моделі зібрано в docs/hardware-components.md,
аргументацію кожного піна — у docs/pinout.md.

## Запуск і незалежна перевірка
Прошивка повідомила init=OK, SYSCLK=48000000 та I²C probe 0x77 result=0.
Виклик HAL_I2C_IsDeviceReady не є драйвером BMP180. У VCD спостерігаються
START, адреса write0x77, рівень ACK і STOP; період SCL10 мкс, частота100 кГц.
Ізольована перевірка під час ЛР2 виявила модельну особливість OUTPUT_OD:
при ODR1 вхід читається як0, тоді як INPUT_PULLUP дає1. Тому цей ACK
не встановлює готовність конкретного сенсора. Для ЛР1 доведено роботу тактової
лінії, UART і LED; повноцінний протокол із перевіреним відпусканням SDA реалізовано в ЛР2.
UART VCD декодувався в sigrok-cli з downsample1000 до1 МГц.
Це усуває непотрібне розгортання довгих пауз із вихідного nanosecond timescale.

Власний live-колектор RFC2217 зберіг послідовні tick35…42 та249…253.
Це докази виконання симулятора, окремі від успішної компіляції.
LED PA5 перемикається раз за цикл; його рівні збережено окремим каналомD5.
Захвати й raw UART належать DewWindow.

## Журнал виявлених проблем
| Симптом і причина | Мінімальне виправлення та перевірка |
|---|---|
| docker не знаходився з shell; каталог executable Docker Desktop відсутній у PATH. | Додано параметр DOCKER; контейнерні збірки виконані за реальним шляхом. |
| Компіляція HAL SPI зупинилася на spi_ex.h; не весь набір залежностей був доданий. | Додано офіційний header тієї ж версіїv1.0.1; build-peripherals-fixed.log підтверджує збірку. |
| Первинний вибір probes PC0/PC1 не відповідав корпусу; універсальний GPIO-регістр не доводить існування фізичного піна. | Звірено DS13867, перенесено на PA1/PA4; фінальний pinout і збірки актуалізовані. |
| .ioc описував лише стартовий UART/I²C, а додаткові ADC/SPI були у ручному init. | Доповнено перелік IP/пінів .ioc, звірено з Platform/board.c; повторна генерація без review не застосовувалась. |
| Початкове декодування довгого VCD не завершувалося швидко: імпорт на1 ГГц розгортав idle-паузи. | Застосовано downsample1000 для UART/I²C; сирий VCD не змінювався, анотації отримані sigrok-cli. |

## Висновки
Відтворювана ARM-збірка і фактичний UART/LED запуск підготовлені.
Відокремлено апаратні можливості C031 від прикладів для Cortex-M4:
майбутні часові вимірювання використовуватимуть TIM3/GPIO замість DWT.
Наступний етап — драйвери, одиниці, помилки та одночасна робота сенсорів у ЛР2.
Повний продукт із журналом і порівняння RTOS ще не реалізовані.
